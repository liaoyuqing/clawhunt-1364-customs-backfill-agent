# 四模块报价、周期与实施方案

本单（报关表回填自动化 Agent）按四个模块分项报价，可整体承接，也可先竞模块一 + 模块二。金额单位为元，周期为工作日。

## 三、领星 / 钉钉接口可行性

### 领星 ERP

- **可行**：领星提供开放 API，产品报关资料、供应商开票资料、采购单明细、FBA 发货计划与货件装箱明细都能通过列表接口分页拉取。仓库里 `core/lingxing_client.py` 已实现鉴权（app_key/app_secret 换 token、或直接用环境变量里的 access token）、请求签名（HMAC-SHA256）、分页、429 限流退避与错误重试，地址与凭据全部从 `LINGXING_*` 环境变量读取，仓库里不含任何凭据。
- **风险**：字段命名与层级随版本可能微调；装箱明细里的「箱数/重量」有时只在 FBA 侧有，采购单侧没有。缓解办法是适配层做字段映射，缺字段走视觉补位并标注 `source.kind = vision`。
- **需要客户提供**：开放平台应用授权（`LINGXING_APP_KEY` / `LINGXING_APP_SECRET`，或一个可用的 `LINGXING_ACCESS_TOKEN`）与所需资源的调用权限、接口版本与配额。

### 钉钉开放平台

- **可行**：钉钉在线表格可用开放平台接口按 sheetId 读写行。仓库里 `core/dingtalk_client.py` 已实现应用凭证换 access_token、读回现有行、按行写回、限流重试，路由路径可用 `DINGTALK_TOKEN_PATH` / `DINGTALK_WRITE_PATH` / `DINGTALK_LIST_PATH` 覆盖以适配不同版本；凭据同样只来自 `DINGTALK_*` 环境变量。
- **风险**：表格列序与列名由客户维护，一旦表头漂移，写入会被列序校验拒绝（`ColumnMismatch`）。缓解办法是列定义放在 `rules/ledger_columns.yaml`，表头变化时只改规则包并升 version。
- **需要客户提供**：钉钉企业内部应用（`DINGTALK_APP_KEY` / `DINGTALK_APP_SECRET`）、目标表格的 `DINGTALK_SHEET_ID`、以及该应用对目标文档的读写权限。

### 视觉模型与界面操作

- **可行**：视觉走 OpenAI 兼容的 `chat/completions`（`VISION_BASE_URL`），请求体带 `image_url`，解析结构化 JSON 后按置信度分流；界面操作走独立执行器（`COMPUTER_USE_BASE_URL`），由视觉结果生成动作后逐条执行。两者都可指向客户自建的内网服务。
- **风险**：截图质量与界面改版会直接影响识别率；低置信度已强制转人工，不会静默写错格。

### 电子税务局

- **部分可行**：填单可以由 Agent 完成，提交必须人工确认。仓库里 `core/etax.py` 已实现草稿生成、`HumanGate` 闸门与提交客户端；没有凭据时只产出草稿与待提交清单，不假装提交。
- **风险**：各地电子税务局的对接方式与授权差异较大，若客户只允许人工提交，则本模块按「Agent 填单 + 人工提交」交付，提交接口不启用。

## 四、实施顺序

1. 规则包与知识库（模块一）：先把七张规则表与品名知识库落地，客户改规则不改代码。
2. 台账回填主流程（模块二）：建行、拆组合、换算、勾稽、待补清单。
3. 视觉与界面补位（模块二）：接口覆盖不到的字段与页面走视觉 + 界面操作。
4. 发票核对（模块三）：七字段差异清单与税局草稿。
5. 本地模型与归档（模块四）：单独虚拟机上线、三项自检、原件归档与审计。

每一阶段都交付可独立运行的源码、对应单测与可复现命令，客户可逐阶段验收。
